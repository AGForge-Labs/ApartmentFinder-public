# Validation boundaries

## Public synthetic check

The reviewed `.github/workflows/public-synthetic-check.yml` supports manual dispatch only. It requires an explicit approval input and the exact reviewed commit; source pushes do not start it.

It uses one standard `macos-15-intel` job, manual dispatch only, with an exact reviewed commit, read-only repository permission, no saved credentials, no matrix, no cache or artifact upload, and a 90-minute hung-job timeout. It explicitly checks Intel x86_64, selects Xcode 26.2 build 17C52 and the installed iOS 26.2 runtime, and refuses an image mismatch. It uses the production project specification and builds the app, Share extension and test targets for a disposable simulator. Simulator signing is ad-hoc; it uses no Apple account, distribution credentials or provisioning profile.

The exact source-checked allowlist in `scripts/public-synthetic-tests.json` selects:

- 117 selected core and public-resource tests: parsing, duplicate deliveries, navigation, GPS freshness, initial framing, manual camera state, completion and rollback
- 71 selected native compatibility tests: personal storage, pack migration/failure, Finder independence, selection races, append, completion/undo, location and actual arrow rendering
- Two fictional OnTrac UI tests: ZIP preview/cancel/empty day, map display, pin-review cancellation, persistence and relaunch

The separate `map-interaction-regression` scope runs exactly those two UI methods plus the existing heading-up/recenter, real-pinch zoom-preservation, and map-style/pan/pin-tip/relaunch methods. It leaves the default 117-Core/73-Native-UI selection unchanged. All five UI identities must exist in the checked-out source and pass exactly once; skips, duplicates and substitutions fail the receipt checks. It uses ordinary test launches, without diagnostic environment switches, private inputs, or artifact uploads. This bounded follow-up addresses risks introduced by projected pin controls; it does not claim the historical full-suite, screenshot, private-data or phone-install gate passed.

### Focused, text-only activation diagnosis

The manual `scope` input defaults to `regression`, preserving the selection above. The separate `activation-diagnostics` scope runs portable checks and exactly three existing test identities: `OnTracImportSetupTests/testFictionalPackAndExactZIPReachTheTwoDayImportRequestOnIOS`, `PublicCatalogBundleStoreTests/testProductionAppBundleLoadsReviewedPublicCatalogWithoutMapImport`, and `OnTracFlowTests/testSourceUnitPinAppearsOnMapAfterOnTracImport`. The production-bundle case decodes the reviewed public resources directly from the actual app bundle, including the current catalog version and fixed uncertainty qualifier, without a private import. It does not freshly validate the other core/native/UI cases or satisfy full acceptance.

Only that scope forwards `TEST_RUNNER_APARTMENTFINDER_SYNTHETIC_DIAGNOSTICS=1` to XCTest; the focused UI test then explicitly enables app diagnostics with a valid isolated UUID store. This uses Apple's [documented test-runner environment forwarding](https://developer.apple.com/documentation/Xcode-Release-Notes/xcode-13-release-notes). App instrumentation is additionally restricted to DEBUG simulator execution.

If the original chooser is absent, the test saves and logs that original failure state, then tries the real production Import Manifest list button in a fresh UUID store with the same toolbar and no-pack banner. It observes picker-request/Cancel/dismissal state without selecting a file. A missing app accessibility Cancel control does not establish that the system picker is absent. Three bounded, main-actor samples also record whether a visible public `UIDocumentPickerViewController` was observed in this app's foreground scenes, without loading views or emitting controller details. This is a positive witness only: SwiftUI does not guarantee that UIKit hosting implementation, so a negative observation remains inconclusive.

The failure branch then makes a fresh-store toolbar comparison with only the visible no-pack banner's hit testing disabled, followed by another fresh-store unchanged toolbar baseline. The pass-through switch requires all existing simulator/DEBUG/isolated-store diagnostic gates and its exact allowlisted probe; ordinary no-pack interaction and release app behavior are unchanged. Each comparison uses one normal tap after unique/enabled/hittable checks and records the same fixed geometry. Baseline failure, pass-through success with matching geometry/action/fixture/request witnesses, and a repeated baseline failure support a banner hit-region cause more strongly than launch order alone. The comparison does not itself repair production layout. The original saved failure is still asserted and the caller returns; comparison success cannot make the original test pass. The embedded ZIP remains in app tmp, so this does not claim Files-provider selection or import coverage.

The [controlled synthetic comparison](https://github.com/AGForge-Labs/ApartmentFinder-public/actions/runs/39295029795) reproduced zero toolbar actions, then one action/two documents/visible chooser with banner hit testing disabled, followed by another zero-action baseline. The latter two launches had identical recorded pre-tap geometry. The normal-layout correction gives the unchanged banner its own stable stack slot above the tab/navigation content instead of a root safe-area inset. The original normal-mode UI flow now also checks that the banner Import button remains present, enabled, hittable and outside the navigation bar. Its action, recording/pending guards and real folder importer are retained. This is accessibility/layout coverage, not end-to-end folder-provider selection. The comparison run's durable container witnesses were unavailable; it establishes no new UIKit picker result or full acceptance.

The app writes up to four small, fixed-schema scalar witnesses, one per allowlisted launch. The collector reads only those exact files inside the disposable simulator app container, rejects unexpected keys/types/enums, symlinks and files over 8 KiB, and emits only approved values. No customer data, catalog contents, error text, filenames, paths, UUIDs or GPS coordinates are emitted. Missing/invalid evidence is distinct from a valid zero count. An early zero snapshot is not conclusive proof that no later action ran: if every later write failed, its in-memory write-failure count could not reach disk. The independent toolbar/list AX comparison and recorded phases must be considered together. Logged screen rectangles describe UI geometry, not the actual injected tap coordinate.

Explicit test screenshot and unrestricted accessibility attachments are disabled in this scope. Xcode may still create internal ephemeral result attachments; none are exported or uploaded. There is no image/artifact upload path.

Diagnostic work has an 85-minute hung-work deadline measured from the first guard step, reserving approximately five minutes inside the 90-minute job timeout for cleanup. Initial guard/checkout/portable steps have diagnostic-only limits of 5/5/10 minutes, and preparation, simulator boot, native work and result processing share the work cutoff. Individual diagnostic tests have a 600-second execution allowance rather than the previous short allowance. Command termination, witness collection and simulator cleanup have bounded waits; original build failures are preserved, and cleanup failure cannot leave an otherwise successful check green. The reserve is a design budget, not an infrastructure timing guarantee. Normal regression mode also uses the practical 90-minute hung-job timeout. Jobs finish when their checks finish; these are safety limits, not target durations.

All other core/native/UI tests remain present. The public check verifies exact passed test identities and rejects zero tests, failures, skips, expected failures, substitutions and missing selected methods. It cannot satisfy private acceptance or authorize release. It validates the sanitized public resource schema/digests and synthetic catalog overlay behavior. It does not run the retained full original-provenance/property suites or the full private validation script.

The public bundle is checked by `python3 -B scripts/public-catalog.py validate --directory data` before compilation. Original private filenames and private input directories remain forbidden in this public job. The two fictional OnTrac UI cases explicitly disable only the public bundle inside their DEBUG simulator/isolated UUID stores, preserving the original no-pack banner regression. Ordinary app launches load the public catalog.

Portable preparation checks:

Artifact verifier unit tests use isolated invented resource digests and simulated screenshots. They test the verifier, not a signed app or native behavior.

GitHub currently lists standard hosted runners as free for public repositories, including `macos-15-intel`: [official runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners). Larger/private runners are outside this proposal. Availability and image contents must be checked again before the first authorized run; see the [official image inventory](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-Readme.md).

Supporting provenance assertions also use `APARTMENTFINDER_PRIVATE_SOURCE_DIRECTORY`. Missing inputs must fail clearly. Synthetic output is not genuine catalog acceptance.

Remaining private-harness blockers:

- Retained JavaScript property/provenance suites still read original `data/` and `research/` inputs. Run them against the immutable original inputs in an isolated private release checkout, or add explicit external input routing. Do not restore genuine files into this public checkout or run them in public Actions.

- Retained genuine-pack native tests need explicit, bounded `TEST_RUNNER_APARTMENTFINDER_PRIVATE_PACK_DIRECTORY` and `TEST_RUNNER_APARTMENTFINDER_PRIVATE_SOURCE_DIRECTORY` forwarding. The legacy address-index parity test must read the original private index, separately from the new public-index parity test.
- `scripts/validate-ios.sh` exports complete result attachments and uses private-dependent suites. It must not be activated in public Actions.

Private acceptance must cover the real installed data, legacy pack and personal-store migration, extension-before-main upgrade, folder-provider access, app-group sharing/protection, search/route refresh, interrupted/cancelled imports, responsiveness, recording/editor state, personal pin corrections and real-device upgrade. Preserve the original phone installation and a verified private backup. Never distribute a blank-catalog or fictional-data build as an upgrade. The public data projection requires a fresh production decode and real-data property separation checks; synthetic fixture passes do not establish those results.
