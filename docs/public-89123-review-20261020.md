## Scoped runtime budget

The accepted catalog was 1,939,725 bytes. The earlier partial draft was 1,997,795
bytes and deferred these 550 operator rows at the 2,000,000-byte limit. The full
catalog is **2,095,340 bytes**, adding 97,545 bytes to the partial draft. It retains
every original object, source citation and all 225 previously added associations.

The limit was a real runtime/import safety boundary: `DataPackPayload` bounds
initializers and file/folder reads, and `PrivateDataPackStore` verifies persisted
generations against those limits. The public bundle had reused the same catalog
reader. There is no documented benchmark rationale for the original exact 2 MB
number. It was not merely a test-fixture policy.

`PublicCatalogSupplement` now gives its fixed, compiled public catalog resource a
dedicated **2,100,000-byte** ceiling, leaving 4,660 bytes. The public validator
mirrors it. The reader reuses regular-file, symlink and cumulative streaming-byte
checks. The generic/private import and generation-verification catalog limit
remains **2,000,000 bytes**. Address-index, point and path limits are unchanged.
No schema, import migration, private pack activation or personal-data rule changes.
Manually selecting a larger folder still exercises the unchanged import bound.

All 775 eligible recovered identities were compared using full street and exact
unit strings: no internal duplicates and no overlap with the prior 6,148 rows.
**All 775 are now admitted**; none remains deferred by the catalog byte budget.
Parkside occurrence labels, Summer floor views and unrelated schematic shapes
still create no extra units, geographic points or verified doors.
